# Review loop

Take the current change to merge-ready: checks green, independent review clean,
commits split and allowed. Focus or range from the user: $ARGUMENTS

Current state:

!`git status --short`

!`git log --oneline main..HEAD || true`

## Loop (at most 3 rounds)

1. **Verify.** Delegate to the `verifier` subagent (`scripts/verify.sh`, or
   `matrix` if a `#[cfg(feature …)]`, a `use` or a module declaration changed). On FAIL, fix
   the cause and verify again before reviewing.
2. **Review.** Delegate to the `code-reviewer` subagent. Give it the task in one
   or two sentences and the diff range. Do not pass your reasoning or a list of
   things you think are fine: an unanchored review is the point. If the change touches CLI
   commands, flags, `rin.yml` fields or defaults, run `docs-sync` in parallel.
3. **Triage** each finding against the code before acting:
   - Real: fix it.
   - Wrong: note why in one line; do not change code to appease the reviewer.
   - Out of scope: list it for the user instead of fixing it.
4. Repeat from step 1 while the last round fixed something of medium severity or
   worse. Stop when the review reports nothing actionable, or after round 3; if you stop at round 3,
   tell the user what is still open.

Resume the same `code-reviewer` for the next round only when its earlier
findings matter for checking the fixes; otherwise start a fresh one.

## Commit

Follow AGENTS.md. In short:

- Split unrelated changes into separate commits; short messages in the repo's
  `area: summary` style (see `git log --oneline -20`).
- Never stage `Cargo.toml` or `Cargo.lock`. If they changed, tell the user what
  changed so they can commit it. The pre-commit hook refuses them from Claude anyway.
- No "Generated by" text anywhere. Use the commit trailer the session asks for.
- Let the pre-commit hook run. Do not pass `--no-verify`.
- Push only when the user asks; never force-push.

## Report

End with: rounds run, findings fixed, findings rejected (with the one-line reason), anything
left for the user (manifest changes, Docker/Linux paths nobody ran here).
