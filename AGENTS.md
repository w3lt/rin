# Rin - Engineering Guidelines

## Verify

- `scripts/verify`: fmt, clippy, tests and the image build (`--no-default-features --features hub,agent`),
  the release workflow's build checks (not its publish dry run). `scripts/verify fast` is fmt + clippy;
  `scripts/verify matrix` adds clippy on every feature subset.
- One test: `cargo test --all-features <name>`. Plain `cargo test` skips the
  end-to-end tests in `src/tests.rs`, which need all three features.
- Git hooks live in `.githooks/`; enable them once per clone with `git config core.hooksPath .githooks`.
  `pre-commit` runs `scripts/verify matrix`; agents must not bypass it with `--no-verify`.
  A cold build takes about two minutes, so give `git commit` and `scripts/verify` a 10 minute timeout.
- Nothing here runs Docker or Linux. Say so when a change touches
  `src/compose.rs`, `images/Dockerfile` or container-only paths, rather than claiming them verified.

## Gotchas

- Images install `rin` from a git revision (`RIN_GIT_REV`, default the `v<version>` tag), not from this working tree.
- `rin-schema.json` is the `rin.yml` contract and is embedded in the binary. Tests use
  `examples/team/rin.yml` as a fixture, so example edits can break tests.

## Changes

- Keep changes focused on the requested task.
- Follow existing conventions before introducing new ones.
- Avoid unnecessary dependencies and abstractions.
- Preserve compatibility across Cargo feature configurations.
- Do not break existing public interfaces without justification.
- Preserve persistent user data during generation, cleanup, and lifecycle changes.
- Before calling a non-trivial change done, run the `review-loop` skill: verify, independent review, fix, repeat.

## Commits

- Write short, clear commit messages.
- Do not include `Generated by` in commit messages.
- Split unrelated changes into understandable commits.
- Manifest files may be modified but must not be committed by the agent.
- Notify the human about manifest changes requiring a commit.

## Others

- Do not include `Generated by` in any message (including commit message, pr description, pr commits and the other messages).
